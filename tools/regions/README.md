# tools/regions — 시·군·구 경계 데이터

Odomap의 "지역 정복"에 쓰는 오프라인 시·군·구 경계를 만듭니다. 앱 코드는 여기 없고 산출물(`out/`)만 앱 에셋으로 씁니다.

```
pip install --user "shapely>=2.1"          # GEOS 3.12+ (coverage_simplify)
python3 -I build_regions.py                 # raw/ 에 원자료 자동 다운로드 → out/regions*.json
python3 -I validate_regions.py              # 지점 테스트 + 시연 주행 → out/demo-region-sequence.json (stdlib만 사용)
```

CC BY 4.0이므로 변경했다는 사실도 알려야 합니다. 위 문구의 "병합·단순화"가 그 표시입니다. 원자료 제공기관이 Odomap을 보증한다는 뜻으로 읽힐 표현은 쓰지 않습니다.

다른 후보를 쓰지 않은 이유는 다음과 같습니다.
- southkorea/southkorea-maps: 2018년 이후 갱신되지 않아 군위군 대구 편입(2023), 강원·전북 특별자치도, 2026년 개편이 빠져 있습니다.
- OSM admin_level: ODbL이라 공유-동일조건(share-alike) 의무가 있고, 2026년 개편 반영 여부도 확실하지 않습니다.
- SGIS 직접 다운로드: 인증키 신청이 필요하고 좌표계(UTM-K) 변환을 따로 해야 합니다. 원자료는 같습니다.

## 단위 결정: "사람들이 말하는 시·군·구" = 230곳

- **포함**: 기초자치단체 227곳(시 75, 군 82, 자치구 70), 세종특별자치시 1곳(단층제라 그 자체가 한 칸), 제주 행정시 2곳(제주시, 서귀포시). 합계 **230곳**.
- **일반구는 상위 시로 병합**합니다. 수원·성남·안양·안산·고양·용인·화성·부천·청주·천안·포항·창원·전주 13개 시의 일반구 39개가 대상입니다(`regions-summary.json`의 `mergedGeneralDistricts`). 이유는 다음과 같습니다.
  1. 사람들은 "수원 다녀왔다"고 말하지 "장안구 다녀왔다"고 하지 않습니다. 배지 이름은 말하는 대로여야 정복감이 생깁니다.
  2. 일반구는 자치단체가 아니라 행정구역입니다(구청장 임명, 의회 없음). 서울·부산 자치구와 급이 다릅니다.
  3. 일반구를 쪼개면 한 도시 안에서 몇 분마다 "새 지역!"이 울립니다(화성시 4개, 창원시 5개). 점수가 큰 도시 쪽으로 쏠리고 운전 중 알림도 지나치게 잦아집니다.
  4. 230은 "전국 시·군·구" 통계(기초 226 + α)와 맞아서 설명하기 쉽습니다.
- 광역·특별시의 자치구(서울 25, 부산 15 등)와 전남광주통합특별시의 옛 광주 자치구 5곳은 각각 별개 단위입니다.
- 병합한 시의 코드는 상위 시 코드(끝자리 0)를 씁니다. 예: 수원시 `41110`, 화성시 `41590`, 창원시 `48120`.

## 산출물 (`out/`)

### `regions.json` — 앱 에셋 (판정용), 약 2.0 MB (gzip 0.7 MB)

```jsonc
{
  "format": "odomap-regions/1", "source": {...attribution...}, "count": 230, "points": 102330,
  "regions": [
    { "code": "41820",            // 5자리 시군구 코드(행정안전부 행정기관코드 앞 5자리)
      "name": "가평군",             // 짧은 이름 (동명 주의: 중구×5, 동구×5, 서구×4, 남구×4, 북구×4, 강서구×2, 고성군×2 …)
      "full": "경기도 가평군",       // 공식 전체 이름
      "label": "경기 가평군",        // UI용 짧은 고유 이름 (항상 유일; 옛 광주 자치구는 "광주 동구", 세종은 "세종시")
      "sido": "경기도", "sidoCode": "41",
      "districts": ["장안구", …],   // (병합된 시만) 포함된 일반구
      "center": [37.8xx, 127.4xx],  // [lat,lng] 도. 폴리곤 내부가 보장되는 점(가장 큰 조각의 pole of inaccessibility)
      "bbox": [minLat, minLng, maxLat, maxLng],        // 정수 마이크로도
      "polygons": [ [ [lat0,lng0,lat1,lng1,…], [구멍 ring…] ], … ] }
  ]
}
```

- 좌표는 **정수 마이크로도**(lat×1e6, lng×1e6)를 **위도 먼저** 평탄 배열로 넣습니다. ring은 닫는 점을 생략합니다(마지막→첫 점 변은 암묵적으로 있음).
- 폴리곤마다 첫 ring이 외곽이고 나머지가 구멍입니다. **even-odd 규칙**으로 판정하면 됩니다. 기준 구현은 `validate_regions.py`의 `ring_contains`/`Index.locate`입니다(bbox로 먼저 거른 뒤 ray casting).
- 이웃 지역끼리 경계를 공유한 채 단순화했습니다(GEOS coverage simplification, 허용오차 60 m). 그래서 단순화 때문에 내륙에서 경계 틈이나 겹침이 새로 생기지 않습니다. 겹침 면적은 0 m²입니다.
- 이웃과 닿지 않는 2만 m² 미만의 섬 8개는 뺐습니다. 독도는 유지했습니다.
- **어느 폴리곤에도 안 들어가는 점**은 바다, 단순화된 해안선 바깥 수십 m, 영암호·부산 수영만 같은 내수면입니다. 이때는 직전 지역을 유지하는 것을 권장합니다(아래 시연 규칙과 같음).

### `regions-outline.json` — "정복 지도" 전국 개요, 약 377 KB

- `sido`: 시도 윤곽 16개(허용오차 700 m, 1.5 km² 미만 섬 제외, 독도 유지)입니다.
- `regions`: 같은 단순화를 적용한 시·군·구 230개 `{code, polygons}`입니다. 방문한 지역을 칠할 때 씁니다. 좌표 형식은 `regions.json`과 같습니다.
- **표시 전용입니다. 판정에 쓰지 마세요.**

### `demo-region-sequence.json`

`tools/routes/out/*.jsonl` 시연 주행을 판정해 지역 진입 순서를 기록합니다. 규칙은 다음과 같습니다.
- 미판정 점은 직전 지역을 유지합니다.
- 새 지역은 30초 이상 연속으로 판정돼야 진입으로 확정합니다. 진입 시각은 그 지역에 처음 들어간 점의 시각입니다.
- 주행 시작 순으로 누적해 처음 방문한 지역에 `firstVisit: true`를 붙입니다.

## 정확도 (build 시 자동 측정)

- 지역별 원본 경계와 단순화 경계 사이 Hausdorff 거리: 중앙값 42 m, p90 72 m, p99 127 m, 최대 226 m(포항시 해안의 작은 돌출부).
- 원본 행정동 내부에서 무작위로 뽑은 육지 점 20,390개 중 다른 지역으로 판정된 점은 6개(0.03%), 어디에도 안 걸린 점은 4개(0.02%)입니다. 모두 경계에서 수십 m 이내입니다.
- 원본 경계 자체도 "실제 행정동 경계와 일부 안 맞음"(admdongkor README)입니다. 강남대로처럼 도로가 곧 구 경계인 곳은 원본으로 판정해도 깜빡이므로, 앱에서는 30초 체류 규칙 같은 히스테리시스를 꼭 두세요.

## 주의

- 남이섬은 법정 경계상 **강원 춘천시 남산면**입니다. `tools/routes`의 `NAMI` 좌표(37.7906,127.5258)도 섬 쪽이라 춘천시로 판정됩니다. 가평나루(선착장)와 가평읍은 가평군입니다.
- 데이터 기준일 이후 행정구역이 바뀌면 `--version`으로 새 판을 받아 다시 빌드합니다. 코드가 바뀔 수 있으니(2026-07 광주·전남 통합 때 시도 코드 `29`/`46` → `12`) 저장된 방문 기록은 코드 대응표로 옮겨야 합니다.
