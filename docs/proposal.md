## 1. 앱 한 줄 소개

계기판 주행거리(Odometer)의 숫자를 지도(Map)로 — 시동만 걸면 내가 달린 길이 저절로 나만의 지도가 되고, 처음 달린 길과 처음 가 본 동네를 세어 주는 Pleos Connect 드라이브 기록 앱.

## 2. 기획 배경

- **운전은 많이 하는데 남는 게 없다.** 우리는 1년에 1만 km 넘게 달리지만, 어디를 달렸는지는 계기판 누적 거리 숫자 하나로만 남는다. 여행지에서 돌아온 길, 처음 넘어 본 고개, 출장길에 지나친 낯선 도시는 금방 잊힌다.
- **폰으로 기록하기엔 번거롭다.** 경로 기록 앱은 출발 전에 켜야 하고, 배터리와 백그라운드 위치 권한 문제로 중간에 자주 끊긴다. 그래서 대부분 기록 자체를 포기한다.
- **차는 기록에 가장 좋은 기기다.** 차는 이동할 때 늘 켜져 있고, 전원 걱정이 없으며, 정확한 위치와 주행 상태(기어·속도·주행거리)를 이미 알고 있다. 운전자가 아무것도 하지 않아도 기록이 남을 수 있는 유일한 기기다.
- **"처음"은 가장 강한 동기다.** 걷기·러닝 앱에서 "처음 걸은 길을 지도에 칠하는" 방식은 사용자가 일부러 새 길로 돌아가게 만드는 강한 재방문 동기가 된다. 이 경험을 차로 옮기면, 익숙한 출퇴근길 대신 새 길을 달려 보고 안 가 본 지역으로 주말 드라이브를 떠날 이유가 생긴다.

## 3. 앱 주요 기능 및 차량 특화 요소

| 기능 | 내용 | 차량 특화 요소 |
|---|---|---|
| **자동 주행 기록** | 주행을 시작하면(기어 D·차속) 백그라운드에서 경로를 기록하고, 주차(P)하면 하나의 드라이브로 정리한다. 운전자 조작 없음. | 차량 주행 상태 신호로 시작·끝을 정확히 판단. 폰 앱처럼 켜고 끄거나 배터리를 걱정할 필요가 없다. |
| **나만의 도로 지도** | 달린 길을 한 장의 지도에 쌓는다. 같은 길은 한 줄로 합치고, 자주 다닌 길일수록 굵게 그린다(1~5단계). | 위치 흔들림·상하행 차로·고가/지하차도를 고려한 도로 그물 알고리즘. |
| **처음 달린 길** | 이번 드라이브에서 처음 달린 거리를 따로 세어 보여 준다. "오늘 42km 중 처음 달린 길 12.4km". | 계기판 누적 주행거리 대비 "내가 개척한 길" 비율 제공(Vehicle SDK Odometer). |
| **시·군·구 정복** | 전국 시·군·구 경계를 앱에 내장해, 처음 들어선 지역을 배지로 모은다. "전국 230곳 중 37곳". | 주행 중 새 지역 진입 시 **음성으로만** 안내(TTS): "양양군 첫 방문이에요." |
| **안 가 본 동네로** | 주말 드라이브 추천: 가까운 미방문 시·군·구를 골라 목적지 또는 경유지로 내비게이션에 바로 넘긴다. | NaviHelper SDK로 경로 요청·경유지 추가, 도착 이벤트로 방문 기록. |
| **도착 후 다시 보기** | 주차하면 오늘 드라이브가 지도 위에 그려지는 짧은 애니메이션과 요약 카드를 보여 준다. | 정차 상태에서만 화면 콘텐츠 제공 — 주행 중 시선 분산 없음. |
| **음성 핀** | "여기 기억해" 한마디로 지금 위치에 메모 핀을 남긴다. | STT SDK 활용. 손을 핸들에서 떼지 않는다. `[확인: STT SDK 제공 시점]` |

**안전 원칙:** 주행 중에는 화면을 쓰지 않는다. 기록은 백그라운드에서, 안내는 음성으로만 하고, 지도·통계·다시 보기는 정차(P) 상태에서 연다(Pleos 주행 규제 정책 준수).

**개인정보 원칙:** 위치 기록은 차량 안에만 암호화해 저장하고 서버로 보내지 않는다. 언제든 전체 삭제할 수 있다.

## 4. 주요 사용 시나리오

**① 출퇴근 직장인 (매일)**
아침에 시동을 걸고 평소처럼 출근한다. 앱을 켤 필요는 없다. 퇴근길에 공사로 우회해 처음 달린 골목 1.8km가 생기고, 집 앞에 주차하자 화면에 "오늘 처음 달린 길 1.8km"가 뜬다. 한 달 뒤 지도를 열면 매일 다닌 출퇴근길은 굵은 선, 가끔 돌아간 길은 얇은 선으로 내 생활 반경이 그려져 있다.

**② 주말 드라이브 커플 (주 1회)**
토요일 아침, 차에서 "안 가 본 동네로"를 누르면 1시간 거리의 미방문 지역 세 곳이 뜬다. 가평군을 고르자 내비게이션이 바로 경로를 안내한다. 가평에 들어서는 순간 "가평군 첫 방문이에요" 음성 안내가 나온다. 돌아와 주차하면 오늘 달린 길이 지도 위에 그려지는 다시 보기가 재생되고, 정복한 지역은 38곳이 된다.

**③ 가족 장거리 여행 (명절·휴가)**
추석 귀성길 400km를 달리는 동안 아이들이 "지금 몇 번째 지역이야?"를 묻는다. 휴게소에 서면 지금까지 지나온 시·군 목록과 지도를 함께 본다. 여행이 끝나면 3박 4일 동안의 경로가 한 장의 카드로 남는다.

**④ 영업·출장 운전자 (주 3회 이상)**
전국을 다니는 영업 사원은 1년 동안 정복한 지역 수와 누적 지도를 보며 성취를 느끼고, 연말에는 "올해 달린 길" 리포트를 받는다.

## 5. 개발 계획

**구현 방식:** Pleos Connect(AAOS) 네이티브 Android 앱. Kotlin, minSdk 28, Gradle 8.x. 계산 엔진은 Android 의존이 없는 순수 Kotlin 모듈로 분리해 단위 테스트로 검증한다.

**핵심 자산:** 모바일 앱에서 실제 사용자와 운영 중인 "걷기 발자취" 엔진(위치 칼만 필터 + RTS 다듬기, 도로 그물 생성, 처음 걸은 길 계산, 지도 타일 분할, 수십 개 시험)을 Kotlin으로 이식하고, 차량 속도·도로 폭에 맞게 규칙 값을 다시 맞춘다.

| 영역 | 구현 | 사용 SDK / API |
|---|---|---|
| 위치 수집 | 포그라운드 서비스에서 1초 간격 위치 수신, 세션 파일에 저장 | **FusedLocation SDK** (`registerFusedLocationCallback`), 대체: NaviHelper `onCurrentLocationInfo` |
| 주행 시작·끝 판단 | 기어·차속으로 드라이브 단위 구분, 주차 시 정리 | **Vehicle SDK** / AAOS `CarPropertyManager` (`GEAR_SELECTION`, `PERF_VEHICLE_SPEED`) |
| 주행거리 연동 | 누적·트립 주행거리 대비 처음 달린 길 비율 | **Vehicle SDK** Odometer (`getTripCurrentDrivingDistance` 등) |
| 도로 그물 엔진 | 칼만+RTS 다듬기 → 도로 그물 → 처음 달린 길·지난 횟수 → z14 타일 | 자체 Kotlin 모듈 |
| 지도 표시 | 종이 질감 기본 지도 + 선택형 실제 지도(오프라인 동작) | MapLibre Android SDK (오픈소스) |
| 시·군·구 정복 | 단순화한 행정구역 경계를 앱에 내장, 진입 판정 | 자체 (공공 행정구역 경계 데이터) |
| 음성 안내 | 새 지역 진입·도착 요약을 음성으로 | **TextToSpeech SDK** |
| 안 가 본 동네로 | 미방문 지역 추천 → 경로 요청 / 경유지 추가, 도착 이벤트로 방문 기록 | **NaviHelper SDK** (`requestRoute`, `addWaypoint`, `onDestinationArrived`) |
| 음성 핀 | "여기 기억해" → 위치 핀 + 메모 | **SpeechToText SDK** |
| 주행 규제 대응 | 주행 중 화면 콘텐츠 제한, 정차 시 전체 화면 | AAOS `CarUxRestrictionsManager` |
| 저장 | 기기 내 암호화 DB, 전체 삭제 | Room + 암호화 |

**개발 일정**
- ~11/15: 엔진 이식·차량 규칙 조정, 지도 표시, 자동 기록, 실제 주행 기록 재생으로 시연 영상 제작, GitHub 공개(소스 + APK)
- ~12/3: 시·군·구 정복, NaviHelper·TTS 연동, 다시 보기, 실차 폼팩터(가로/세로 창) 대응, Pleos 에뮬레이터 검증

## 6. 기대효과 및 발전 가능성

**사용자 가치**
- 아무것도 하지 않아도 쌓이는 "나의 운전 기록" — 차를 탈수록 지도가 채워지는 수집 경험.
- 새 길·새 지역을 달릴 이유를 만들어 주말 드라이브와 국내 여행을 늘린다.
- 차량 안에서만 저장되는 기록이라 위치 데이터 걱정이 적다.

**타깃 고객**
- 1차: 주말 드라이브·국내 여행을 즐기는 2040 운전자, 가족 단위 장거리 여행자
- 2차: 출장·영업으로 장거리를 자주 달리는 운전자, 신차를 산 지 얼마 안 된 오너

**예상 MAU·리텐션 (가정 기반 추정)**
- 시장: 현대차그룹은 2026년 2분기 Pleos Connect를 처음 적용하고 2030년까지 2,000만 대 이상에 탑재한다는 목표를 발표했다.
- 자동 기록이라 **주행만 하면 활성 사용자**가 된다. 앱을 일부러 켜야 하는 서비스보다 이탈이 구조적으로 적다.
- 가정(초기): 국내 탑재 차량 50만 대 × 앱 설치율 5% = 설치 2.5만, 그중 월 1회 이상 기록 열람 60% → **MAU 약 1.5만**.
- 가정(확대): 국내 탑재 300만 대 → MAU 약 9만. 해외 마켓 출시 시 행정구역 데이터만 바꾸면 같은 구조로 확장 가능.
- 리텐션 목표: 30일 열람 리텐션 35% 이상. 근거 — 기록이 쌓일수록 지도의 가치가 커지는 구조(전환 비용), 시·군·구 정복의 수집 동기, 주간 요약 음성 안내.

**향후 확대**
- **차 + 걷기 통합 여행 발자취:** 차로 달린 길과 내려서 걸은 길(모바일 걷기 발자취)을 하나의 여행 기록으로 합친다.
- **지자체·관광 연계:** "우리 군 첫 방문" 배지와 지역 관광지·스탬프 투어 연계, 방문 인증 리워드.
- **가족·친구 공유:** 같은 차를 쓰는 가족의 지도 합치기, 여행 카드 공유.
- **연간 리포트·프리미엄:** "올해 달린 길" 리포트, 다시 보기 고화질 영상, 지도 테마.
- **EV 특화:** 처음 써 본 충전소, 지역별 전비 기록.
